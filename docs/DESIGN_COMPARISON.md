# 2단계 — A/B/C 디자인 비교

작성 2026-09-18. 프리뷰: `npm run dev` 후 `http://localhost:5173/` (비교 목록) · `/compare` (나란히) · `/concepts/a|b|c/...`. 스크린샷·나란히 비교 이미지: `docs/previews/`.

## 통제 조건 (같게 만든 것)
- 12개 상품(포켓몬 4·원피스 3·리프트바운드 2·용품 3), 같은 가격·재고(판매중/재고 적음/품절/예약), 6개 세트, 242개 판본, 8건 샘플 시세 관측, 3개 이야기, 같은 카피.
- 같은 라우팅·상태(장바구니·저장·토스트)·구매 로직(`BuyPanel`, `MobileBuyBar`, `FilterSheet`, `PriceSummary`). 방향은 `data-concept` 속성과 CSS 토큰, 그리고 홈/상품/세트의 **구성(composition)** 만 바뀐다. 별도 앱·세 벌의 커머스 코드 없음.
- 중립 자리표시자(상품·카드·캐릭터·워드마크) 공통 사용. 캔버스 1440 / 390, 구현은 반응형.

## 방향별 관찰 (실제 프리뷰 기준)

### A. 취향 편집숍
- **홈**: 비대칭 히어로(큰 카피 + 살짝 기울어진 '같이 들여다보는 프레임': 오들리가 084 카드를 바라보고 편집 이유가 붙음) → 텍스트 빠른 진입 → 큐레이션 1대+2소 → 눈여겨볼 카드 4장(선정 이유 포함) → 상품 8개 → 이야기.
- **상품 상세**: 이미지 좌 / 구매 패널 우(스티키). 아래에 세트 특징 + 대표 카드 4장(편집 이유) 균형. 모바일은 하단 구매 바.
- **세트 상세**: 헤더에 프레임 장치(A만 캡션 포함) → 소개 → 상품 → 힛카드(이미지 카드 + 컴팩트 시세) → 전체 카드 6열 그리드(표 전환 가능).
- 장점: 첫 화면에서 브랜드 태도(같이 보는 친구)와 판매 품목이 동시에 읽힘. 카드 매력 → 세트 → 상품으로 흐르는 여정이 자연스럽다.
- 약점: 큐레이션·이야기 블록이 상품 그리드 앞에 있어 '지금 살 것'까지 스크롤이 가장 길다(1440에서 상품 그리드 시작 ≈ 2,000px). 편집 문구 품질에 결과가 크게 의존.

### B. 컬렉터 아카이브
- **홈**: 검색이 첫 요소(큰 검색창 + 세트 코드/번호 힌트, 오들리 64px) → 세트 색인 표 → 편집 추천 카드 표(시세 열 포함) + 신규 등록 → 12개 상품 6열 밀집 → 이야기 리스트.
- **상품 상세**: 컴팩트 구매 패널, 이미지 아래 판본 정보 표(카테고리·세트·발매·구성·규격). 세트 요약도 표 2개(세트 사실 / 편집 추천 카드 + 시세).
- **세트 상세**: 헤더 우측에 특징·가공 카드, **스티키 서브내비**, 힛카드는 표(번호·레어도·아트·시세·선정 이유), 전체 카드 8열 그리드 또는 표.
- 장점: 판본·수록·시세 접근이 가장 빠르고 정확하다. 상태 배지(표본 부족·갱신 지연·매칭 미확인)가 한눈에 비교된다. 정적이어서 가볍다.
- 약점: 홈이 데이터 사이트처럼 보임. 모바일에서 표가 가로 스크롤(힛카드 표 5열 중 시세 열이 잘림 → 스크롤 표시 필요). 브랜드 고유성이 가장 약함.

### C. 플레이풀 쇼룸
- **홈**: 오프블랙 장면 + 초대형 카피(2줄 어긋남) + 상품 패널 + 큰 오들리(320px, 등장 연출 1개·reduced-motion 시 정지) → 굵은 테두리 진입 타일 4개 → 진열 3개(1 크게) → 눈여겨볼 카드 가로 스트립 → 상품 8개 → 이야기 2개.
- **상품 상세**: 상단 장면(브랜드 틴트 + 오들리)만 다르고 **구매 패널은 공통 그대로**. 대표 카드 4장(중간 크기).
- **세트 상세**: 틴트 배경 프레임에 카드 + 200px 오들리, 힛카드 가로 스트립(큰 카드), 전체 카드 4열 큰 그리드.
- 장점: 첫 인상의 기억성이 가장 크다. 게임 진입 타일이 모바일에서도 큼직하고 누르기 쉽다. 구매 영역은 안정적으로 유지됨을 확인.
- 약점: 히어로가 첫 뷰포트의 62%를 차지해 상품 진입이 접힘 아래로 밀린다(1440 기준 CTA가 y≈700). 캐릭터 크기 때문에 어린이 브랜드로 읽힐 위험. 세로 스트립은 데스크톱에서 카드 6장이 다 보이지 않음.

## 평가표 (제안 가중치 · 임의 채점 아님)
사용자 조사 전이므로 점수를 넣지 않는다. 각 항목에서 **무엇을 확인해야 하는지**만 적는다.
| 항목 | 가중치 | 확인 방법 | 현재 관찰 |
|---|---|---|---|
| 구매·탐색 명확성 | 25 | 과제 1·2·3 수행 시간·오류 | 세 방향 모두 자동 QA 통과. 첫 화면→상품 도달은 B < C ≈ A(스크롤 거리) |
| 정보 신뢰와 구분 | 20 | 시세 상태·판본 구분 인지 | B가 표에서 가장 명확. A/C는 컴팩트 요약으로 동일 정보 제공 |
| 브랜드 고유성 | 20 | 첫 인상 회상 | C > A > B |
| 모바일·접근성 | 15 | 390 조작, 키보드, reduced-motion | 공통 컴포넌트라 동일. B의 표 가로 스크롤은 개선 필요 |
| 속도 | 10 | 번들·이미지 | 동일 번들(공통 코드). C의 히어로 연출도 CSS만 |
| 확장성 | 10 | 아트토이 등 다른 상품군 | A의 큐레이션 구조와 B의 색인 구조가 유리. C의 진입 타일은 품목 증가 시 재설계 |

## 추천 (선택 전 잠정)
**A의 홈 + B의 세트/시세 정보 질서 + C의 제한된 대표 장면 1개.**
- 홈: A 구성 유지. 단, 상품 그리드를 큐레이션 바로 뒤로 올려 '지금 살 것'까지의 거리를 줄인다.
- 세트 상세·카드 상세: B의 스티키 서브내비와 힛카드 표(모바일은 카드형으로 접기), 전체 카드는 이미지/표 전환 유지.
- 대표 장면: C의 히어로 장치는 홈 히어로 **한 곳**에서만, 높이를 첫 뷰포트 45% 이하로 제한. 오들리 크기는 A 수준(≈120px)과 C 수준(≈300px) 사이에서 선택.
- 이것은 비교 후 사용자가 선택할 때까지 **결정으로 기록하지 않는다** (docs/DECISIONS.md D-08 참조).

## 선택 질문 (4개 축)
1. 홈의 인상: A(편집숍) / B(검색·색인) / C(장면) 중 어느 첫 화면이 ODDLYS답게 느껴지는가? 스크롤 전 판매 품목 인지가 되는가?
2. 상품을 찾는 방식: 큐레이션에서 발견(A) / 검색·색인(B) / 진입 타일(C) 중 기본으로 삼을 것은?
3. 정보 밀도: 세트 상세의 힛카드·전체 카드를 표 중심(B)으로 갈지, 이미지 중심(A/C) + 표 전환으로 갈지?
4. 캐릭터 비중: 오들리를 대표 장면에서 크게(C), 포인트에서 큐레이터처럼(A), 필요한 자리에서 작게(B)?
답은 "A/B/C" 하나가 아니라 축별로 받는다. 조합을 선택하면 3단계에서 토큰·핵심 화면을 그 조합으로 확정한다.
